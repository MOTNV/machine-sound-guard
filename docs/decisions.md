# 결정 기록

되돌리기 어려운 결정(주제, 모델, 장비, DB, 계약)을 날짜순으로 적는다. 형식: 날짜, 결정, 이유, 버린 선택지 (2개 이상 비교).

## 2026-11-03 주제: 기계 이상음 감지기

- 결정: ESP32-S3 마이크로 기계(시연은 탁상 선풍기)의 소리를 듣고, 평소 소리와 다르면 이상으로 판단해 기록한다. 쌓인 이상 점수로 고장 전조를 본다 (예지 정비, 산업 안전).
- 이유: 혼자 하는 프로젝트라 데이터 모으기가 가장 큰 부담인데, 이상 감지는 정상 소리만 배우면 된다. 마이크만 쓰므로 부품을 더할 필요가 없고, 날개에 테이프를 붙이는 것만으로 안전하게 이상을 재현해 시연할 수 있다. 시간에 따라 쌓이는 이상 점수는 DB에 남길 이유가 분명하다.
- 버린 선택지: 자전거 후방 차량 경고 (물체 검출이라 데이터·정확도 부담이 크다), 졸음 감지 (96×96에서 눈 감음 구분이 불안정), 낙상 감지·화재경보음 알리미 (방향이 맞지 않았다).

## 2026-11-03 시연 기계는 PC가 만드는 가상의 기계 소리로 한다

- 결정: `tools/`의 가상 기계가 모터 소리(기본 주파수 + 배음 + 잡음)를 만들고, 이상(날개 불균형, 베어링 마모, 이물질 걸림, 점점 나빠짐)을 섞는다. PC 스피커로 틀어 ESP32 마이크가 듣게 하고, 같은 소리를 학습 데이터와 CI 테스트에도 쓴다.
- 이유: 실제 기계 없이도 정상·이상을 원하는 만큼 같은 조건으로 만들 수 있고, 안전하다. 지난 프로젝트에서 보드 대신 가짜 장치로 개발·검사한 방식과 같다.
- 버린 선택지: 실제 탁상 선풍기 (이상을 재현하려면 날개를 건드려야 하고, 매번 같은 소리가 나지 않는다), PC 쿨러 (소리가 작아 마이크로 잡기 어렵다).

## 2026-11-03 DB는 내 PC의 Docker(서버 + Postgres)

- 결정: `server/`의 docker compose로 API 서버와 Postgres를 띄운다. ESP32는 같은 Wi-Fi에서 서버로 HTTP POST한다.
- 이유: CI에서 서버·DB까지 통째로 띄워 검사할 수 있고(수십 초), 인터넷 없이 시연할 수 있다. ESP32에서 HTTPS·키를 다루지 않아도 된다.
- 버린 선택지: Supabase (서버를 켜 둘 필요가 없지만, CI에서 로컬 Supabase를 띄우는 데 1분 30초 이상 걸렸고 ESP32에 키를 둬야 한다).

## 2026-11-03 모델은 직접 학습한다 (멜 대역 특징 + K-means 이상 감지)

- 결정: 1초 소리에서 멜 대역 32개의 평균·흔들림과 저음 대역 3개를 뽑고(67개 값), 정상 소리만으로 K-means(군집 8개)를 학습한다. 가장 가까운 군집 중심까지의 거리를 기준값으로 나눈 것이 이상 점수다 (1 이상이면 이상). 파이썬(`model/`)이 기준 구현이고 ESP32 C 코드가 같은 수식을 쓴다.
- 이유: 학습부터 ESP32용 코드까지 전부 코드라서 CI가 모델을 다시 학습하고 감지율·오경보율을 매번 검사할 수 있다. 실험에서 이상 4가지 모두 세기 0.3부터 100% 감지, 정상 오경보 1초당 0.33%, 모델 약 2.7KB.
- 버린 선택지: Edge Impulse (모델을 바꿀 때마다 웹에서 직접 학습·내보내기를 해야 해 CI로 자동화하기 어렵다), 저음 특징 없이 멜 대역만 (날개 불균형 세기 0.3 감지율 6%).

## 2026-11-03 현장 보정을 넣는다, 경보는 웹 대시보드로만

- 결정: 설치 후 평소 소리를 2분 듣고 ESP32가 스스로 K-means와 기준값을 다시 만든다 (기본 모델과 같은 방식, 같은 코드). 경보는 웹 대시보드에만 띄운다.
- 이유: 기계마다 정상 소리(회전 속도·설치 위치)가 달라 기본 모델만으로는 다른 기계에서 오경보가 난다. 경보 채널을 하나로 두면 혼자 만들 범위가 줄어든다.
- 버린 선택지: 기본 모델만 쓰기, 텔레그램 알림 추가.
